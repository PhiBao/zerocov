Architecture

How the API is put together

A small, production-shaped Express service: stateless JWT auth, role guards, four resource routers over an in-memory repository, and a global error handler. The specifications in openapi.yaml and docs/ are the source of truth for behavior.

Auth model

JWT bearer tokens

Access tokens (15m) and refresh tokens (7d) are HS256-signed from JWT_SECRET / JWT_REFRESH_SECRET. Every authenticated route goes through authenticate(), which returns 401 for missing, malformed, invalid, or expired tokens — the EXP-TOKEN-401 requirement.

Roles

employee creates and submits own expenses, reads own reports. manager resolves assigned approvals and reads team expenses/reports. admin can act on all approvals and lists.

Spec divergences found and fixed

1 · Token handling. Invalid, tampered, and expired JWTs returned 500 because the middleware re-threw every JWT error. EXP-TOKEN-401 and openapi.yaml require 401. Fixed in src/auth/middleware.ts; 3 tests fail before the fix.

2 · Amount validation. POST/PATCH /expenses bypassed the shared validator, accepting non-integer, non-finite (1e999 → Infinity), and above-cap amounts. openapi.yaml declares amount: integer, minimum 1. Fixed via isValidAmount(); 5 tests fail before the fix.

No assertion was weakened to make a test pass — a project rule enforces this.
